## 1. 执行摘要

欧盟与美国的买家、零售商及监管机构正将**可验证的供应链证据**作为市场准入的条件。欧盟的《企业可持续发展报告指令》(CSRD)、《企业可持续发展尽职调查指令》(CSDDD) 与《反毁林条例》(EUDR)，以及美国《维吾尔强迫劳动预防法》(UFLPA) 执法体系，均要求进口商以**有据可查、细粒度、防篡改**的证据证明所购商品在生产过程中不存在毁林、强迫劳动或未披露的 ESG 风险。中国出口商尽管实力雄厚，却常常因为这些评估而未达标——原因在于其证据多为**纸质记录、分散零碎、且无法独立验证**。

TrueSight DAO 运营着一套**已在生产环境中运行**的供应链溯源技术栈，目前已在实体产品线（单一庄园仪式级可可）上落地。该技术栈包括：

1. **单品级二维码序列化**——每一件实体商品都带有唯一二维码，可解析为结构化的溯源档案。
2. **单品谱系清单**——机器可读的 JSON 历史记录，涵盖来源、加工、保管及事件（仅可追加）。
3. **区块链锚定（TrueChain）**——在一条经许可、可审计的链上对每一条记录进行防篡改哈希。
4. **身份与凭证体系（认证链）**——每一方（工厂、农场、审计机构、承运商）都持有可验证的身份；每一个事件都是一条*认证链*。
5. **文件公证**——官方文件与影像资料（审计报告、认证证书、用工记录）被存储并关联到其所涉商品。
6. **公开验证界面**——任何利益相关方扫码即可查看该商品完整的溯源信息、ESG 相关数据与证据链。

本白皮书阐述这一已在可可产品上验证的技术栈，如何被改造以帮助中国制造商满足欧盟与美国的 ESG 和溯源要求、提升出口评级，并将合规从成本转化为竞争优势。

## 2. 问题：合规缺口

### 2.1 欧盟与美国如今的要求

| 法规体系 | 对进口商（进而对出口商）的要求 |
|---|---|
| **欧盟 CSRD / ESRS** | 覆盖价值链的可持续发展报告，包括范围三排放与供应链 ESG 数据。欧盟买家必须向供应商收集这些数据。 |
| **欧盟 CSDDD** | 强制性的全价值链人权与环境尽职调查——识别、预防、补救——无论供应商位于何处。 |
| **欧盟 EUDR** | 商品的无毁林证明：生产地块地理定位、风险评估，以及每批货物的尽职调查声明 (DDS)。 |
| **美国 UFLPA / CBP（含 2026 年 6 月操作指南）** | 对与新疆或实体清单关联的商品推定存在强迫劳动；要求**供应链图谱**、**批次级溯源记录**、第三方社会合规审计及强迫劳动风险评估。 |

### 2.2 中国出口商为何在这些评估中失利

- **证据碎片化**——数据分散于纸质记录、ERP 系统孤岛与多层供应商之间，无法整合为一份订单级证明。
- **缺乏单品级身份**——若每件商品没有序列化标识，买家便无法验证某项声明（产地、批次、劳工、碳足迹）针对的是*这一件*商品，而非一份泛化的证书。
- **缺乏独立认证**——自行声明的文件无法独立验证，且日益被视为漂绿风险。
- **缺乏防篡改能力**——电子表格与 PDF 事后可被修改，审计方无法信任其完整性。
- **数据本地化摩擦**——不同司法辖区的买家和监管机构要求不同的数据管控，拖慢了证据交换。

结果：有能力的中国制造商在**ESG 评级中被降级**，甚至在**边境被扣留**（仅美国 CBP 一家，2025 财年至 2026 财年初即报告逾 17,000 起与 UFLPA 相关的扣留），尽管其运营本身并无问题。

## 3. 我们已拥有的：TrueSight 谱系技术栈

以下技术栈**已在生产环境**用于单一庄园可可。每个组件均已具备代码、数据与公共基础设施。

### 3.1 单品级二维码序列化（已验证：1,457+ 件商品）

- 每一件实体商品都带有一个**序列化二维码**（例如 `2024OSCAR_20260121_12`）。
- 二维码即**单品身份**：它可解析出农场、年份、批次及其完整的账本历史。它刻意区别于零售 GTIN——GTIN 只标识产品*类型*。
- 既有二维码可继续使用、无需改动；新商品一次操作即可完成标签（二维码 + 农场 + 产地）与对应 JSON 清单的铸造。

### 3.2 单品谱系清单（`lineage-assets`）

- 每件商品一个 JSON 文件：`qr_id`（二维码标识）、`asset_type`（资产类型）、`status`（状态）、`current_holder`（当前持有者）、`lineage`（农场、地区、收获年份、SKU），以及一个**仅可追加的 `events` 事件数组**（铸造 → 寄售 → 售出 → …）。
- 数据模型具有明确的**可扩展性**：新增资产类型（`textile_lot` 纺织批次、`electronics_batch` 电子产品批次、`agri_lot` 农产品批次等）无需改动外壳结构。
- 每个文件的 Git 历史即每件资产的审计轨迹；任何利益相关方都能独立获取某件商品的文件。

### 3.3 区块链锚定（TrueChain）

- 一条经许可的以太坊网络（Geth，Clique 权威证明共识），配有专用登记合约：`ShipmentRegistry`（货运登记）、`FarmRegistry`（农场登记）、`ProductRegistry`（产品登记）、`InvoiceRegistry`（发票登记）、`QRCodeRegistry`（二维码登记）、`SalesReceiptRegistry`（销售凭证登记）、`ContributionRegistry`（贡献登记）。
- 记录通过哈希载荷**仅可追加、防篡改**；镜像服务将哈希写入链上并返回交易哈希，将表格行 ↔ 链上记录双向关联。
- 工厂无需任何钱包：证据在后台完成锚定，任何人无需区块链客户端即可验证。

### 3.4 身份与凭证体系（认证链）

- 与我们的人类凭证平台架构平行：**每一方都有自己的密钥对**；每一个事件都是一条*认证链*——由已知行为方对可验证事实作证。
- 既适用于人（工厂管理者、审计师、工人代表），也适用于资产。

### 3.5 文件公证

- 一个公开仓库，用于上传并存储可验证供应链流程的官方文件与影像资料——审计报告、认证证书、用工记录、工厂照片/视频——并关联到其所涉商品。
- 文件经过哈希与时间戳处理，从而可证明"这份证书属于这一批次"。

### 3.6 公开验证界面

- `truesight.me/qr/?id=<qr_id>` —— 扫描任何一件商品即可查看其溯源时间线、状态、持有者与事件。
- 产品验证列表（`truesight.me/physical-assets/serialized/`）—— 覆盖所有商品的可搜索、可筛选索引。
- 同一界面还可生成**出口就绪的尽职调查文件包**：产地、批次记录、认证声明与关联文件。

### 3.7 跨辖区数据本地化（已设计，尚未部署）

该架构被设计为可拆分至按辖区划分的仓库（`lineage-assets-china`、`lineage-assets-eu` 等），各仓库**托管于所在辖区**以满足数据本地化规则，跨境查询通过 API 而非数据复制完成。这对中国出口商尤为重要——数据须留在中国境内，而欧美买家需远程核验证据。

## 4. 技术栈如何映射到中国出口工厂

| 步骤 | 工厂活动 | 我们的组件 | 产出 |
|---|---|---|---|
| 1 | 登记工厂、设施与供应链图谱 | 身份与凭证体系；农场/设施登记 | 已核验的行为方身份、供应链图谱 |
| 2 | 为每件出口商品序列化 | 二维码铸造（标签 + 清单） | 商品二维码 + JSON 清单 |
| 3 | 记录生产事件（原料入厂、质检、批次、用工、能耗） | 谱系事件（仅可追加） | 批次级溯源记录 |
| 4 | 附上证据（审计、认证、用工文件、照片） | 文件公证 | 每件商品关联且经哈希的证据 |
| 5 | 全部锚定上链 | TrueChain 镜像服务 | 防篡改哈希 + 每条记录的交易哈希 |
| 6 | 生成订单级尽职调查文件包 | 验证界面 / 报告生成器 | 满足 CSRD/CSDDD/EUDR/UFLPA 的文件包 |
| 7 | 买家/监管机构验证 | 扫码或打开文件包 | 数秒内完成独立验证 |

这就是我们为可可运行的**同一条流水线**——产地农场 → 加工 → 保管 → 销售——推广到任何一件制造型出口商品。

## 6. 试点计划

### 6.1 阶段 0 —— 对齐（第 0–2 周）

- 在高关注度行业（纺织、电子、农产品）中确定 1–3 家出口工厂，且其拥有欧美买家关系。
- 确认目标市场及每位买家/监管机构所需的具体证据。
- 通过现有中国合作伙伴渠道（Jerri/Ling 团队、Aora 项目网络）对接。

### 6.2 阶段 1 —— 入驻一家工厂（第 2–6 周）

- 登记工厂身份与供应链图谱；为一个出口订单铸造二维码。
- 为该订单建立谱系清单（原料 → 生产 → 质检 → 包装）。
- 通过公证附上现有文件（审计、认证、用工记录）。
- 锚定至 TrueChain；生成演示用尽职调查文件包。
- 成功指标：买家接受该文件包作为充分证据。

### 6.3 阶段 2 —— ESG 数据模型与评级（第 6–12 周）

- 将谱系事件映射至 ESRS 数据点与买家 ESG 问卷。
- 接入可选的第三方审计师认证集成。
- 基于实时数据（而非静态 PDF）生成定期 ESG 报告。

### 6.4 阶段 3 —— 规模化（第 3–12 个月）

- 按辖区数据本地化（lineage-assets-china 等）。
- 行业模板（纺织 / 电子 / 农产品）与多工厂推广。
- 面向买家的验证门户与市场集成。

## 7. 诚信与治理护栏

- **本平台不做合规认证。** 它让证据变得*可验证*——声明的完整性被锚定，而声明的真伪由认证行为方与独立审计方负责。这正是反漂绿的设计。
- **认证模型**：每个事件都注明认证该事件的行为方；行为方可被识别；法规要求处由第三方审计。
- **仅可追加**：记录只能通过追加更正来修正，绝不可编辑历史。
- **数据本地化**：按辖区托管使出口数据留在所需辖区境内。
- **开放验证**：任何利益相关方无需专门软件即可验证——扫码即可。
